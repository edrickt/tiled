## Per-area verdicts

### 1. Dispatch, focus, pruning, multi-canvas aggregation — sound

- A slot hotkey prunes confirmed deaths first, then resolves the requester and
  its canvas (`TilingController.swift:326-337`), collapses an expanded
  requester before plan execution (`:346-351`), applies the canvas outcome
  through one coordinator effect path (`:408-431`), and updates the menu
  (`:379-386`). The already-assigned strict no-op stays side-effect free while
  still answering the hotkey channel (`:367-378`).
- Focus observation reports only canvas-key moves, so moves within one canvas
  never redraw the glyph (`:281-289`); a Space report reasserts stale
  canvases, resynchronizes the focused canvas, and updates the menu (`:296-306`).
- Pruning runs before every hotkey, evict, untile-all, untile, undo-chapter,
  and expand entry (`:329`, `:1405`, `:816`, `:1453`, `:969`, `:1509`), and the
  runloop timer compares the whole occupant count before updating the menu
  (`:206-214`). Only sustained `.dead` readings prune; `.unknown` never does
  (`:751-784`, comment `:746-750`).
- The menu aggregates every visible canvas grouped per display, withheld-Space
  canvases included, while hidden Spaces stay managed but off-menu
  (`:1345-1373`). The absent-display frame is never adopted: re-resolution
  skips unattached displays (`:626-630`), an absent display reads as not
  visible (`:1699-1707`), and the stale mark clears only on a reassert with
  real geometry (`:517-535`). Pinned by `DisplayIdentityTests.swift:129-259`
  and `ScreenOwnershipTests.swift:20-143`.

  `:303-314`, `:316-333`.
