## Per-area verdicts

### Focused-canvas keying — solid, ticket 06 pinned

`menuSnapshot(space:)` reads one canvas for the whole pass and derives every unscoped
field from it: `canUndoDisplacement` from `canvas.undoStack`, `displacedCount` from
`canvas.displacedCount`, `hasSplitterBackup` from the same canvas, and `untileCount`
from `canvas.tiledCount`, with a comment calling out that re-resolving focus there would
title the row from a different canvas than the menu describes
(`Sources/tiled/AppDelegate.swift:542-584`, count read at `:579-582`).
`MenuModel.items` gates the undo/restore rows on the focused canvas while the window list
stays aggregated across every visible canvas (`Sources/tiled/MenuModel.swift:237-249`);
Untile appears only when `untileCount > 0` (`:292-298`), so "Untile 0 Windows" cannot
render, and the splitter row survives on a parked backup alone (`:299-308`).
The cross-canvas mismatch cases the prior audit asked for are pinned:
`Tests/tiledTests/MenuModelTests.swift:306-325` (empty focused canvas omits Untile/Reset),
`:327-341` (live undo chapter renders with no tiled windows), `:354-368` (Untile counts
the focused canvas only), `:386-402` (parked restore row survives the empty canvas).
The single-key update pass (menu and glyph resolved once via `refreshPass`) is pinned at
`Tests/tiledTests/AppDelegateMenuTests.swift:232-256`, including the in-place
`menuNeedsUpdate` path (`Sources/tiled/AppDelegate.swift:1057-1070`).
Docs match: `README.md:150-156` (untile row omitted on an empty focused canvas),
`:162-172` (glyph and focused-canvas rows follow focus; window list aggregates),
`CHANGELOG.md:49-53`.

### One-receipt menu + announcement path — solid for four actions, ticket 07 pinned

The controller builds one `ActionReceipt` after the action, carrying owning canvas,
performed flag, sticky notice, and exactly one sentence; the delegate only presents it
(`Sources/tiled/ActionReceipt.swift:1-20`, builder `Sources/tiled/TilingController.swift:1629-1639`).
Evict (`:1404-1436`), Untile All (`:815-849`), single-window untile (`:1449-1480`), and
Undo (`:936-954`) all return that receipt, and every entry point presents it:
menu rows (`Sources/tiled/AppDelegate.swift:875-886,1006-1013`) and hotkey routes
(`Sources/tiled/HotkeyActionRouter.swift:60-70`) share `present(_)` (`Sources/tiled/AppDelegate.swift:925-937`).
No-op and refusal paths answer exactly once via the receipt's no-op sentence; the
background-canvas refusal names its display (`Sources/tiled/TilingController.swift:1471-1479`,
`Sources/tiled/MenuText.swift:172-181`), and the menu overlay carries a background
receipt bounded by focus generation (`Sources/tiled/AppDelegate.swift:586-608`, pinned by
`Tests/tiledTests/AppDelegateMenuTests.swift:258-316`).
Tile/expand hotkey paths stay silent on success and speak only refusals/deferrals through
the controller-owned mapping (`Sources/tiled/TilingController.swift:339-403,1508-1539`),
so no success sentence can outrun the action. The Action → selector wiring for all 16
cases is pinned (`Tests/tiledTests/AppDelegateMenuTests.swift:364-403`).
Docs match: `README.md:190-194`, `CHANGELOG.md:44-48`.
Residual gap: the splitter actions never joined this path — filed as M2 below.

## New findings (provisional IDs; orchestrator assigns final report IDs)

### M1 — Dead title helpers keep the pre-ticket-06 all-canvas count (suggested LOW)

- Severity: LOW (dead code; no runtime effect today; trap for a future edit).
- Evidence: `Sources/tiled/AppDelegate.swift:749-759` defines private
  `undoDisplacementTitle` and `untileAllTitle`; repo-wide grep shows no caller — the live
  menu path builds both titles from the snapshot in `MenuModel.swift:281-298` instead.
  The dead `untileAllTitle` counts `controller.tiledWindowsInfo` (every visible canvas),
  the exact mismatch ticket 06 removed.
- Reachable sequence: none at runtime (uncalled). A future edit wiring these helpers back
  into the menu would reintroduce "Untile N Windows" counted across canvases.
- Test gap: no test can pin dead code; deletion is the pin.
- Fix direction: delete both helpers; the snapshot path (`MenuModel.swift:287-298` with
  `AppDelegate.swift:577-582`) already owns both titles.

### M2 — Splitter actions stay outside the one-receipt path (suggested LOW)

- Severity: LOW (no false announcement observed; menu/hotkey asymmetry by construction).
- Evidence: menu `resetDividers` announces fixed sentences without a controller verdict
  (`Sources/tiled/AppDelegate.swift:888-906`, sentences at `:893-895,905`), while the
  hotkey route calls `controller.resetDividers()` and announces nothing
  (`Sources/tiled/HotkeyActionRouter.swift:72-74`). The controller returns `Void`/`Bool`,
  never an `ActionReceipt` (`Sources/tiled/TilingController.swift:857-898`), unlike the
  four receipt-covered actions. The restore sentence is also worded twice: canvas notice
  (`Sources/tiled/TilingSpace.swift:1504`) and delegate literal (`AppDelegate.swift:894`).
- Reachable sequence: press ⌥⇧R with an empty focused canvas — the controller resets
  fractions silently (no receipt, no sentence); the menu row for the same action cannot
  exist there (`MenuModel.swift:299-308`), so the two surfaces describe the action
  differently by construction. A refused splitter write has no refusal sentence on either
  surface (reset clears `error` at `TilingSpace.swift:1490`).
- Test gap: no test asserts what a splitter action says (or stays silent for); receipt
  tests cover evict/untile/undo only.
- Fix direction: return an `ActionReceipt` from the splitter actions (or document the
  silence as intended), route both menu and hotkey through `present(_)`
  (`AppDelegate.swift:925-937`), and source the restore sentence once.

### M3 — Slot-list expectations derive from the production constants under test (suggested LOW)

- Severity: LOW (structural tests only; headers and layout-change rows are literal).
- Evidence: `Tests/tiledTests/MenuModelTests.swift:171` compares the submenu's slots to
  `SlotPresentation.quartersQuads + SlotPresentation.quartersHalves`, and `:194-198` to
  the sixths groups — the same constants `MenuModel.items` iterates to build those rows
  (`Sources/tiled/MenuModel.swift:185-190,208-219`). An omission in both places passes.
- Reachable sequence: static (test-only circularity); e.g. a slot dropped from
  `SlotPresentation` and the model together stays green.
- Test gap: no literal full-list pin for either layout's submenu in this slice's tests.
- Fix direction: assert one literal slot-name list per layout (as ticket 17 did for rects
  and the refusal string), keeping the constant-derived form as a secondary shape check.
