## Verdicts

### 1. One shared write policy — solid, still single-sourced

`FrameWriter` remains the one module every write path shares. The four
outcomes are named once (`Sources/tiled/FrameWriter.swift:9-28`): expected
(`.written`), already-correct skip (`.skippedNoOp`), refused (`.refused`),
and deferred off-Space (`.deferredOffSpace`). The ordering inside
`write` is visibility first, then the already-correct skip, then the write
with the echo armed before it (`Sources/tiled/FrameWriter.swift:90-121`).
The F18 shape stays pinned: a skipped write seeds the drag baseline
(`Sources/tiled/FrameWriter.swift:106`; pinned end to end by
`Tests/tiledTests/TilingSpaceTests.swift:65-87`), and a refused write cancels
the armed echo and reseeds from the live frame
(`Sources/tiled/FrameWriter.swift:117-120`; pinned by
`Tests/tiledTests/FrameWriterTests.swift:129-147`). The clamp repair still
repins against the canvas visible frame, never the window frame
(`Sources/tiled/FrameWriter.swift:129-140,151-174`; pinned by
`Tests/tiledTests/FrameWriterTests.swift:164-230`). No second policy exists:
`DragTracker` holds no write path of its own (only closeness helpers at
`Sources/tiled/DragTracker.swift:734-745` and the live-splitter decide path
at `Sources/tiled/DragTracker.swift:621-664`, which reads the canvas visible
frame but writes no window).

### 2. `Result.stands` read sites — solid, every path reads the one predicate

The glossary contract (`CONTEXT.md:100`) holds: every write path treats only
`.refused` as failure. Read sites: undo re-place
(`Sources/tiled/TilingSpace.swift:496`), re-house move
(`Sources/tiled/TilingSpace.swift:723-726`, deferral flag included), restore
(`Sources/tiled/TilingSpace.swift:960`), with the contract restated at the
`applyLayout` and `writeRects` definitions
(`Sources/tiled/TilingSpace.swift:1066-1073,1162-1168`). Slot requests fold
the outcome through `place` (`Sources/tiled/TilingSpace.swift:884-920`,
deferral retained at `:915-918`) and expand/collapse through
`writeExpandedFrame` (`Sources/tiled/TilingSpace.swift:1469-1479`, callers at
`:1380-1399,:1415-1446`). A deferred write therefore stands everywhere with
the same meaning, and only a genuine refusal rolls a slot request back
(`Sources/tiled/TilingSpace.swift:885-909`, F1 shape preserved).

### 3. Swipe-back reconcile — solid, cross-canvas discard confirmed

The swipe-back path is intact: workspace report → stale reassert of the
visible canvases (`Sources/tiled/TilingController.swift:291-319`), with the
visible frame refreshed on the same pass
(`Sources/tiled/TilingController.swift:620-631`). The canvas reassert lands
deferred restores, then deferred slot/expand/collapse requests, then the
rect plan (`Sources/tiled/TilingSpace.swift:1598-1631`), over the one shared
reconcile skeleton (`Sources/tiled/TilingSpace.swift:988-1003`). The ex-F5
rule holds on all three claim shapes: a slot request claims only when it
lands, defers, retiles into an already-held slot, or refuses while keeping
its slot (`Sources/tiled/TilingController.swift:353-364`); an undo re-place
whose write stands discards on every canvas
(`Sources/tiled/TilingSpace.swift:496-502`, including the retained-slot
refusal at `:511-519`); a landed or deferred expand discards
(`Sources/tiled/TilingController.swift:1528-1536`); a fresh record clears its
own canvas (`Sources/tiled/TilingSpace.swift:212-220`). The swipe-back
silence is pinned by
`Tests/tiledTests/SpaceIndependenceTests.swift:65-79` ("the swipe back never
writes the discarded pre-tile restore"). A refused first slot request still
leaves the source canvas restore live
(`Sources/tiled/TilingSpace.swift:520-524`), matching the claim rule — the
review-fix refinement from `b4251b8` is present, not regressed.

### 4. `FrameWriter` → `DragTracker` coupling (A1) — status: unchanged

**A1 status line: unchanged — no ledger module exists; the tolerance import
and the split ownership persist. Not improved, not regressed.**

`FrameWriter` still reads the gesture tracker's closeness helper and
tolerance (`Sources/tiled/FrameWriter.swift:104,154`) and the canvas still
reads the same tolerance for achieved-edge reconcile
(`Sources/tiled/TilingSpace.swift:1677`). The expected-write memory is still
split across the tracker (`Sources/tiled/DragTracker.swift:229-242,265-297`),
the coordinator's pending-verification table
(`Sources/tiled/TilingController.swift:452-469`), and the canvas deferred
maps (`Sources/tiled/TilingSpace.swift:74-116`). No file named or shaped
like a ledger exists in `Sources/` (grep for `ledger` is empty). The `b4251b8`

effect behind injected closures (`Sources/tiled/FrameWriter.swift:42-55`),

## New findings

### F21 (LOW): a released handle can still answer the focused-window query inside the memoization window

- Severity: LOW.
- Evidence: `focusedWindow` returns the memoized handle without revalidating
  it (`Sources/tiled/LiveWindowGateway.swift:355-367`); `release` drops the
  element, pid, frame source, handlers, and baseline but never clears the
  memoized focus answer (`Sources/tiled/LiveWindowGateway.swift:440-454`).
- Reachable sequence: focus a window (memoizes the handle) → its death is
  confirmed and the coordinator releases it → a slot action within 0.05 s
  reads `focusedWindow` and receives the released handle. Downstream the
  frame read answers nil, so the likely outcome is a refusal message rather
  than the "no focused window" answer — a transient, self-healing
  misdirection, never a stuck state.
- Test gap: `focusedWindow` has no hermetic test (it needs the system-wide
  AX read); nothing pins post-release focus answers.
- Fix direction: clear the memoized focus answer in `release` when it names
  the released handle (and route its stamps through the injected `now`, see
  T9). Duplicate status: new, not a duplicate of any prior finding.

### T9 (LOW): the focus-answer memoization lifetime is untestable — its stamps bypass the injected clock

- Severity: LOW.
- Evidence: the Space-table cache honors the injected `now`
  (`Sources/tiled/LiveWindowGateway.swift:786-793`), but the focus cache
  stamps `Date()` directly at write and both reads
  (`Sources/tiled/LiveWindowGateway.swift:356-357,361,365`), and the focus
  callback clears it through the shared live instance
  (`:1156-1161`).
- Reachable sequence: any test wanting to pin the 0.05 s memoization or its
  invalidation must sleep on wall time; none does, so the lifetime is pinned
  only by the live suite.
- Test gap: no test covers focus memoization hit, expiry, or callback
  invalidation.
- Fix direction: thread `now` through the focus-answer read/write/clear
  paths the way the Space cache already does. Duplicate status: new; the
  Space-cache half of ticket 15 is done, this is the focus-cache remainder.

### F22 (LOW): README still partitions the live adapter to the live suite only

- Severity: LOW (docs accuracy).
- Evidence: `README.md:285-289` says the unit suite "drives the pure engine
  through `FakeWindowGateway`" while "the live adapter
  (`LiveWindowGateway`) is exercised by `scripts/run-repro.sh`". Since
  ticket 15, the adapter's Space cache, observer routing, destroy delivery,
  adoption, release pruning, and write-pair recovery run hermetically in
  `Tests/tiledTests/LiveGatewayWiringTests.swift:11-397` with no grant.
- Reachable sequence: a reader auditing hermetic coverage concludes the
  adapter is live-only and misses the existing seam.
- Test gap: none (docs only).
- Fix direction: one sentence naming the hermetic adapter seam beside the
  live-suite sentence; optionally name the residual live-only paths (focus
  resolution, element registry fallback, app-list assembly). Duplicate
  status: new, not a duplicate.
