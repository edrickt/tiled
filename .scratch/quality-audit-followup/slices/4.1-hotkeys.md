- Base: `3c3a432` per `docs/plans/major-features-quality-audit.md:223`.
- Method: read-only trace of `Sources/tiled/HotkeyService.swift`,
  `HotkeyBinding.swift`, `HotkeyAction.swift`, `HotkeyActionRouter.swift`

## Verdicts

### 1. Registrar seam (ticket 13, ex-T1) — confirmed pinned

**Ticket-13 re-verification line: confirmed pinned — every DONE bullet
reproduces in the current tree; no regression.**

- Registrar adapter at the seam: `HotkeyRegistrar` answers an `OSStatus`
  plus an opaque token (`Sources/tiled/HotkeyService.swift:21-26`); the
  production adapter wraps Carbon (`:32-63`), and the suite stands in a
  fake (`Tests/tiledTests/HotkeyRegistrationTests.swift:226-275`).
- Registration of every enabled action: 22 requests, one per action with
  its live binding, Carbon id, and `'TILD'` signature
  (`Tests/tiledTests/HotkeyRegistrationTests.swift:36-79`).
- Disabled-action skip: a binding with no keycode registers nothing
  (`Sources/tiled/HotkeyService.swift:247-248`), pinned for one action
  and for all actions at once
  (`Tests/tiledTests/HotkeyRegistrationTests.swift:83-117`).
- `failedActions`: a non-`noErr` answer — or `noErr` with no token —
  names the action and leaves no token behind, without stopping the rest
  (`Sources/tiled/HotkeyService.swift:254-262`;
  `Tests/tiledTests/HotkeyRegistrationTests.swift:121-146`).
- Reload: retires the whole old set before registering the edited store,
  recomputing failures both ways
  (`Sources/tiled/HotkeyService.swift:230-233,243-244`;
  `Tests/tiledTests/HotkeyRegistrationTests.swift:151-203`, including the
  register-after-teardown ordering pin at `:176-182`).
- Teardown: deinit retires every live token
  (`Sources/tiled/HotkeyService.swift:222-224,235-240`;
  `Tests/tiledTests/HotkeyRegistrationTests.swift:207-220`).
- Landed as `572de00`; the `CHANGELOG.md:11-14` entry describes exactly
  this behavior.

### 2. One route (ticket 16, ex-T4/A4) — confirmed pinned

**Ticket-16 re-verification line: confirmed pinned — the dead table is
gone and the callback consumes the one derived mapping; no regression.**

- One declaration: `actionByID` derives from `HotkeyAction.allCases`
  (`Sources/tiled/HotkeyService.swift:163-164`), so an action cannot be
  present in one map and absent from another by construction.
- `route(forHotKeyID:)` is a direct read of that mapping (`:166-168`).
- The Carbon callback routes through it (`:293`) and answers
  `eventNotHandledErr` for unknown ids (`:293-295`), letting the event
  fall through to other apps.
- No second mapping exists: grep for `actionByID|route(forHotKeyID` hits
  only the declaration, the read, the callback call site, and the test.
  The old `route(forHotKeyID:slotByID:)` signature is gone.
- Pinned by `Tests/tiledTests/HotkeyServiceTests.swift:135-159`, whose
  comment now states the production callback consumes the exact mapping
  — true on the current tree, unlike the ex-T4 shape.
- Landed as `9856939` (on top of the seam work in `702f938`).
- The performer half is pinned too: `HotkeyActionRouter.dispatch` is an
  exhaustive branch over every action
  (`Sources/tiled/HotkeyActionRouter.swift:19-28`), tested against a
  literal expectation per action rather than a lookup derived from
  production (`Tests/tiledTests/HotkeyActionRouterTests.swift:31-53`),
  and the live performer forwards each route to the same controller or
  delegate entry point the equivalent menu row uses (`:56-156`).

## New findings

### H1 (LOW): the Carbon callback body runs only against live events

- Severity: LOW (suggested).
- Evidence: `carbonCallback` parses the event parameter, resolves
  through `route`, and hops to the main queue
  (`Sources/tiled/HotkeyService.swift:280-298`). The suite pins `route`
  and the performer, but nothing drives the callback itself — the
  installer is stubbed out in every registration test
  (`Tests/tiledTests/HotkeyRegistrationTests.swift:26-31`), and no test
  synthesizes a Carbon event.
- Reachable sequence: a regression inside the callback (wrong parameter
  name, a dropped async hop, a bypass around `route`) stays green; only
  the live suite would notice.
- Test gap: no seam for the callback's resolve-and-invoke step.
- Fix direction: expose a test-only entry that maps an id to a handler
  invocation without a Carbon event, or inject the main-queue hop, so
  the callback body is pinned the way `route` already is. Duplicate
  status: new — the residual of T4/ticket 16, not a duplicate; ticket 16
  closed the dead-table half, this is the untested-callback remainder.

### H2 (LOW): the shared handler outlives service teardown

- Severity: LOW (suggested).
- Evidence: registrations retire on deinit
  (`Sources/tiled/HotkeyService.swift:222-224`), but the handler lives
  on the process-wide shared context (`:187-203`) and is never cleared
  alongside them. A replaced service's closure stays armed until the
  next assignment.
- Reachable sequence: replace the service (or release it) without
  assigning a new handler → a Carbon event invokes the stale closure.
  Bounded today: the AppDelegate call site captures weakly
  (`Sources/tiled/AppDelegate.swift:180`), so the worst outcome is a
  dropped fire, never a use-after-release.
- Test gap: no test pins handler behavior across service replacement;
  the registration tests never touch `handler`.
- Fix direction: state the ownership rule at the handler declaration
  (who clears, and when), or pin replacement ordering through the
  registrar seam. Duplicate status: new, not a duplicate of any prior
  finding.

## Considered and dismissed

- Two force-unwraps in the slice (`Slot.hotkeyID` over its own
  `allCases` at `Sources/tiled/HotkeyService.swift:93`; the callback's
  `userData` at `:292`, always installed with the shared context at
  `:266-278`): safe by construction, each guarded by a test that would
  fail first (sequential-id pin, registration construction). Not filed.
- `CarbonHotkeyRegistrar.unregister` ignoring a foreign token with a log
  line (`:56-62`): unreachable in production, where the registrar only
  ever sees tokens it issued. Not filed.
- Per-action `registrationRecovery` copy
  (`Sources/tiled/HotkeyAction.swift:88-96`): consumed by AppDelegate
  and the Shortcuts tab (`Sources/tiled/AppDelegate.swift:773`;
  `Sources/tiled/SettingsShortcutsTab.swift:292,656`); its wording pins
  live in slices 4.2/4.3. Noted as a boundary, not filed.
- `Slot.allCases.count` growth toward the reserved 995–999 ids: the
  suite pins the ordering margin
  (`Tests/tiledTests/HotkeyServiceTests.swift:46-50`). No realistic
  growth shape threatens it. Not filed.
