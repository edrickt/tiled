## Design Specificity Verdict

**LLM assessment (unanchored, before detector):** Unmistakably tiled end to end. The product character lives in behavior, not pixels: reversible destruction (undo names the evicted), parked bulk re-enables, previews drawn from the layout engine's own cell sets, no-op retile taught as safety, consequence-named buttons ("Untile All 3 Windows"), per-column splitters with ordering guards. A generic window manager could not wear this unchanged - the swap/evict/switchLayout ruleset and its surface language are bespoke. Stock AppKit rendering is the right call for an Operate utility; expression lives in the details. The risk is no longer identity but discoverability: the best teaching surfaces (Welcome, hover previews) are the least presented.

## Overall Impression

The whole directory reads as one coherent product decision - safe-to-explore tiling with reversible destruction - executed consistently from AX observer callbacks to menu titles. Nothing structural is missing; every deduction comes from the last mile between capability and user: silent hotkey paths, an unpresented Welcome, mouse-only geometry. Biggest opportunity is making the app speak at the moments it currently goes quiet.

## What's Working

1. **Safe-to-explore is a system, not a slogan.** No-op retile, confirms with consequences on the button, one-step undo that names what returns, conflicts that preserve the old binding, parked bulk restores, refusal messages that name the app that refused. Every destructive path was given a reverse gear.
2. **Previews cannot lie.** Exhaustive TileCell switch (new cell = compile error), the same cell sets as the layout engine, accent-on-track system colors free in both appearances, mouse-only hover that never disturbs the keyboard path, hidden previews ignored by VoiceOver.
3. **Failures are surfaced, never only logged.** `failedSlots` + settings-fallback warning in the menu with live custom labels, restore failures named per window, SMAppService failure reverts the checkbox with an explanation. The menu's status section is an honest instrument panel.

## Priority Issues

- **[P1] First launch never presents Welcome.** `show(selecting: .general)` is the default and no launch path selects `.welcome`; a normal first launch opens nothing at all, and the hidden-icon recovery path opens General. The README promises "First launch opens Settings on a Welcome tab." The Welcome tab is built at index 0 but never selected.
  - **Why it matters:** the single best teaching moment (one demo combo + lit geometry + pointer to hover previews) is invisible on day one; Jordan meets 17 rows of vocabulary instead of one demonstrated action.
  - **Fix:** on first run (`!didDismissWelcome`), open Settings selecting `.welcome`; select Welcome in the recovery path too when the flag is unset; when `start()` fires after a permission wait, open Welcome once.
  - **Suggested command:** `/impeccable onboard`
- **[P2] The hotkey path - the primary interface - is mute.** `handle(slot:)` silently returns when there is no focused window; retile-own-tile is a deliberate silent no-op; a refused resize surfaces only in the menu the user isn't looking at. All reassurance (notices, errors, counts) lives in the menu; hotkey users get none of it.
  - **Why it matters:** the user presses ⌥⇧U, nothing moves, and the app offers no theory - dead hotkey? wrong window? permission lost? Silent no-ops train users to press harder, not smarter.
  - **Fix:** a failure haptic (NSHapticFeedbackManager defaultAlignment) and/or a brief status-item attention cue on no-focus and refusal paths; keep the safe no-op, announce it subtly.
  - **Suggested command:** `/impeccable harden`
- **[P2] Sixths submenu is 11 flat items.** Settings groups with counts and collapse; the Tile Focused Window submenu lists 6 corners/middles + 3 thirds + 2 two-thirds undifferentiated, exceeding working memory at the moment of action.
  - **Why it matters:** the in-the-moment picker produces skip-and-guess; users memorize 2-3 slots and ignore the rest of the layout they installed the app for.
  - **Fix:** separators + disabled sub-headers (Corners / Thirds / Two-Thirds) mirroring the Quarters/Sixths split one level up.
  - **Suggested command:** `/impeccable layout`
- **[P2] Hover previews are mouse-only; the keyboard path gets no geometry.** `RowHoverOwner` reveals on mouseEntered only; tabbing through recorder buttons shows nothing. Related: while a recorder is armed, the local monitor swallows Tab/arrow keyDowns, so keyboard users can't tab away mid-record except via Esc (which they must already know).
  - **Why it matters:** recognition-over-recall fails exactly for the users who need it most; the armed recorder is a mild keyboard trap.
  - **Fix:** reveal the row preview on focus as well as hover; let Tab/Escape-cancel semantics pass navigation keys through while armed (Esc still cancels).
  - **Suggested command:** `/impeccable harden`
- **[P3] Preview pixels still never eyeballed.** Gap/radius math reads sane (64x40 → 1pt gap/2pt radius; 160x100 → 2/4), but `.quaternaryLabelColor` track in Dark Mode may render near-invisible and hover reveal is instant with no fade.
  - **Why it matters:** taste lives in pixels; a muddy miniature teaches nothing.
  - **Fix:** one manual launch pass (Welcome tab, hover each section, both appearances), then tune radius/spacing/timing.
  - **Suggested command:** `/impeccable polish`
