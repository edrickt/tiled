# Mutation gate runs mutants in parallel copy-sandboxes

Status: accepted

The mutation gate (`tools/mutation/mutate.py`) ran one mutant at a time — patch, full `swift test`, restore — ~15 minutes for 84 mutants on the 8 GB M1 Air and growing with the table, which made landing any change a burden. We decided to run K mutants concurrently (default 4, half the 8 cores; `--workers` override), each in its own throwaway copy-sandbox of the current working tree under the OS temp dir: the master copies `Sources`, `Tests`, and `Package.swift`, hands out mutants as workers free up (dynamic pull, because per-mutant cost varies with file size), and merges results into today's summary, `build/mutation-results.json` contract, and exit code. Verdict semantics stay verbatim: every mutant is still judged by the full 655-test suite, survivors and UNRESOLVED still fail the gate, and stage gates and CI are untouched.

Copy-sandboxes rather than `git worktree` because the tool runs mid-stage on a dirty tree: a copy captures uncommitted sources and tests exactly, and the real tree is never mutated — retiring the restore-from-memory failure mode. Workers run `swift build --build-tests` then `swift test --skip-build` (spike: 6.0 s wall for four workers vs 10.1 s with one `swift test` per cycle, same verdicts), and must always rebuild before running, because a stale build silently runs the wrong binary. Before fan-out the master runs one unmutated suite in the main tree; a non-green baseline aborts as unresolved instead of scoring mutants.

Measured in the spike: warm mutant cycles ~6 s per worker; the full table projects to ~3–4 minutes. The cold fan-out burst (four fresh builds) pushed ~5 GiB of swapouts on the 8 GB machine without stalling any worker — K is dialable if that becomes painful.

Considered options: `git worktree` plus an overlay of uncommitted changes (rejected: replicates dirty state fragilely, precisely when the tool is used); a per-mutant verdict cache (deferred: few cache hits mid-stage; unnecessary once parallel clears the bar); mutation switching precompiled into production sources (rejected: invasive, unnecessary); running the test bundle directly with `xcrun xctest` (rejected: bypasses SwiftPM orchestration and would silently skip swift-testing tests if any are added); static sharding (rejected: file-size-dependent costs leave workers idle).
