Tiled 0.2.1 is a fixes release: a dragged screen edge now snaps back when
you release it, and a run of drag-gesture fixes makes title-bar drags and
drag-outs behave under fast, slow, and programmatic-looking gestures.

## Install

1. Download `Tiled-0.2.1.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-0.2.1.zip.sha256`.

## What's fixed since 0.2.0

- **Screen edges snap back.** Dragging an edge that sits on a screen edge
  (the top edge of a right two-thirds window, say) moves no splitter, and
  the release used to settle nothing — the edge stayed wherever you let go.
  Any edge movement now settles at mouse-up, and the release reassert pulls
  the fixed edge home. In a corner drag mixing a screen edge with a real
  splitter, the splitter's new position is kept and only the screen edge
  snaps back. A reassert the app's own live-resize session overrides is
  recognized and re-issued once, so the edge comes home even when the first
  write loses that race.
- **Title-bar drags no longer expand the tile.** Apps that silently absorb a
  placement write (rounding to their own grid) made the first drag tick
  carry a slightly different size than the target, which read as an edge
  grab and yanked a splitter by the full drag distance. Ticks now classify
  by what a hand can do: windows do not resize during a title drag.
- **Fast flings until out.** A fast drag out of a tile coalesces in
  Accessibility to a single far tick, which the drag-end's two-tick rule
  read as a programmatic jump and snapped back. A drag decided at the
  physical mouse-up is a hand gesture by definition and untiles past the
  distance.
- **Drag-outs decide at the drop.** The title-bar drag ends at mouse-up
  like an edge drag, instead of waiting out the 0.5 s move-silence debounce
  that left the slot marked occupied and the neighbours un-reflowed for a
  second or more.
- **The drag-out distance is halved:** ~50 pt of title-bar drag (was ~100)
  releases the slot and leaves the window where dropped.
- **A re-housed blocker absorbs the vacated tile.** Tiling a right-third
  window into the left third no longer leaves the right third empty: the
  displaced left two-thirds window re-houses into the middle third and ends
  up as the right two-thirds.

### Under the hood

- A release reassert the app's own resize session overrides is detected in
  the drag tracker and re-issued once as a grid re-write; a departing
  animation cannot trip the repair.
- The README's published test counts are checked in CI
  (`scripts/check-test-count.sh`), so they cannot drift silently.
- The focused live suites launch their host windows as a real bundle, so a
  crowded desktop cannot make a suite click the wrong window.

## Quality

- 680 hermetic unit tests over the pure engine through `FakeWindowGateway`,
  an 86-mutant audit where every injected bug is caught, and the live
  end-to-end suites (including a new focused corner-drag latency probe) for
  the pre-release pass.
- No network, no telemetry, no persisted window state; see
  [`SECURITY.md`](https://github.com/edrickt/tiled/blob/master/SECURITY.md).
