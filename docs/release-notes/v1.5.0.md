Tiled 1.5.0 stops resizing new windows. A window you open keeps the size
and position its app gives it; Tiled no longer shrinks it to a quarter of
the screen.

## Install

1. Download `Tiled-1.5.0.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.
   (Each reinstall needs one re-grant: the ad-hoc signature changes
   every build.)

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-1.5.0.zip.sha256`.

## What changed

- **New windows open at their app's size.** Tiled used to resize every new
  window to the quarter footprint, keeping its top edge, so windows opened
  at a size their app never asked for. That resize is gone; a new window
  now stays exactly where and how its app opened it.
- **New windows are still managed.** Tiled still tracks each new window as a
  floating, untiled window on its own display's canvas, so a slot hotkey
  acts on it exactly as before. Tiled has never auto-tiled windows and
  still does not.
- **No mid-drag snap.** The resize used to wait for mouse-up when a window
  was born during a drag (tearing a tab off Firefox). With no resize there
  is nothing to wait for: the window stays where the app drops it.
- **Nothing is written for a new window.** A new window on a hidden Mission
  Control Space is recorded on that Space's canvas; Tiled no longer parks a
  deferred quarter-size write to land when you swipe back.

Everything else is unchanged: quarters and sixths, the eleven shared slot
keys, live edge resizing, undo, expand, evict, and the whole-title-bar
double-click gesture all work as in 1.4.2.
