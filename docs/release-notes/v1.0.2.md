Tiled 1.0.2 is a bug fix for edge resizing. Dragging to expand a window
over a neighbour that is already at its app's minimum size used to snap
the drag back at mouse-up; now the edge you dragged keeps the position
you gave it.

## Install

1. Download `Tiled-1.0.2.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-1.0.2.zip.sha256`.

## What changed

- **A minimum-size neighbour no longer pulls your drag back.** Every app
  has its own floor below which it refuses to shrink. Dragging a shared
  edge to expand a tile over such a neighbour used to end with the
  neighbour's floor winning: the splitter was pulled back to the edge the
  neighbour could reach and your window shrank to abut it, undoing the
  drag at mouse-up. Now the neighbour keeps its minimum size exactly where
  it stands, pinned to the screen edge it already held, and the expanding
  window keeps the edge the drag reached. The two overlap, the expanded
  window in front, and the overlap is stable across display changes and
  Space swipes. Dragging the splitter back past the neighbour's achieved
  edge makes the two flush again.
- A neighbour that lands a few pixels *short* of its target by rounding
  (Terminal sizes to whole character rows, for example) still owns the
  splitter, so the gap that case used to leave stays closed.

See ADR 0004 in the repository for the decision behind the new rule.
