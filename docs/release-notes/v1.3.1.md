Tiled 1.3.1 fixes new windows never being sized: every new window —
including a tab torn off into its own window — lands at quarter size
again, and a mid-drag birth waits for the drop instead of fighting it.

## Install

1. Download `Tiled-1.3.1.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.
   (Each reinstall needs one re-grant: the ad-hoc signature changes
   every build.)

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-1.3.1.zip.sha256`.

## What changed

- **Births route again.** Creation notifications arrive with the newborn
  window's element, never the subscribed app element, so the app
  element's hash could never route them and every birth was silently
  dropped. Tiled now reads the owner off the delivered element, with the
  token map as fallback.
- **Focus no longer shadows births.** A focus read adopts a window before
  its creation notification is processed; only observed bindings shadow
  a birth now, and the newborn loop reuses the focus-first handle
  instead of forking a second identity.
- **Mid-drag births wait for the drop.** A window born while the mouse
  button is down (tearing a tab off Firefox) parks unsized and lands at
  the quarter footprint at the drop point on mouse-up. Tiling it
  mid-drag supersedes the parked size.
