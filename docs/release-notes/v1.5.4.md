Tiled 1.5.4 is a correctness release built from a full audit of the app and its
test suite. Every change below was reproduced before it was fixed; the report is
in `.audit/code-quality-2026-11-24.md` in the repository.

## Install

1. Download `Tiled-1.5.4.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.
   (Each reinstall needs one re-grant: the ad-hoc signature changes
   every build.)

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-1.5.4.zip.sha256`.

## What changed

- **Undo no longer leaves a window covering its neighbour.** A window that had
  been expanded kept its expanded entry when an undo chapter re-placed it, so the
  canvas still called it full-screen while it visibly sat on a tile — and the
  next display change, swipe back, or splitter reset re-filled it over the
  window that had just been placed beside it. Undo and a swap now end the
  expansion when the move lands, and restore it when the move is refused.
- **Recording a shortcut can no longer switch every hotkey off.** Arming the
  recorder retires all seventeen registrations, and the local key monitor only
  sees keys while Tiled is active. Clicking another app to test the new window
  you just tiled left the recorder armed forever and every global shortcut dead,
  with nothing on screen to explain it. Losing activation now ends the recording
  the same way tabbing away does.
- **A hung app can no longer hang Tiled.** When a liveness probe failed, Tiled
  read the frame of every window the app owned to decide whether one was gone,
  on the main thread, with a one-second Accessibility timeout per read. An app
  with fifty windows could stop Tiled for the better part of a minute. The reads
  are now bounded by a time budget and an identity-listed window is read only for
  its own frame, so absence is still provable.
- **The recorder passes system-standard combos through.** ⌘Q, ⌘W, ⌘Tab and ⌘Space
  are no longer swallowed by an armed recorder or bound to a slot; they keep
  doing what the system and the app menu say they do.
- **A closed window's slot frees when the window is really gone.** The destroyed
  notification released the slot on one dead reading, skipping the confirmation
  window that exists precisely for the transient where a live window's probes
  fail (a lid close, a display teardown). It now starts the death clock and
  confirms.
- **A first tiling whose frame cannot be read is refused, not half-applied.** It
  used to record a zero pre-tile frame, so untiling later wrote nothing and left
  the window in its tile while a neighbour grew over it. The request is now
  refused before anything is displaced, and the menu says why.
- **Accessibility revocation reaches Settings while it is open.** The window kept
  claiming Tiled was trusted after the permission had been taken away in System
  Settings, while the menu already knew. The two surfaces agree again.
- **A hidden menu-bar icon on an untrusted first run opens Settings.** That
  combination could leave an app with no surface at all — no icon to click and no
  welcome window — and the hide-icon dialog promised a Settings window that
  never opened. The relaunch it asks for now always lands somewhere.
- **Reset/Restore Splitters no longer blames an app for a dead window.** It is
  the one action that neither pruned nor applied its outcome, so a window not yet
  pruned surfaced as an "app refused" line.
- **A window on a withheld Space follows its display when it can.** A slot request
  that arrives before the display names its Mission Control Space now migrates the
  window onto the canvas the display names, instead of deferring every write. When
  both canvases already hold windows there is still no merge; that remains open.
- **Refusals and undo chapters read correctly.** One app's refusal is counted
  once, not once per corrective pass ("Couldn't move 2 windows" for one window);
  a named deferred-restore failure is no longer overwritten by a generic
  request-count sentence; and an empty untile-all placeholder can no longer evict
  the oldest real undo chapter from a full stack.
- **A write an app silently ignores is now reported.** Restores, reflows and undo
  re-places sent their frame and never looked again, so a window that ignored the
  write left the screen and the canvas disagreeing with no error. They are
  verified now and narrated like every other write.

### Performance

- Slot actions sweep liveness only over tiled records, once per action, instead
  of every managed window (including every adopted birth) and twice for
  untile-all and Tile Here.
- The display list and the Space inventory are cached and invalidated on the
  events that can change them, instead of re-enumerated per mouse-move event,
  per menu row, and per action.
- The reassert reuses the frame the write policy already read instead of reading
  every window a third time.
- Accessibility trust is read once per invalidated pass instead of asking the TCC
  daemon on every refresh — which was once per drag tick.
- With the menu-bar icon hidden, a refresh returns before rasterizing the glyph.
- Re-subscribing to an app Tiled already observes no longer re-reads that app's
  window list.

Everything else is unchanged: quarters and sixths, the eleven shared slot keys,
live edge resizing, undo, expand, evict, drag-out, per-display and per-Space
canvases, and remappable shortcuts all work as in 1.5.3. The suite is 1226 tests
(1180 before), and the exhaustive undo replay still checks 18,818 edges and
11,931 undo checks with no signature drift.
