Tiled 0.2.2 is a one-fix release: detaching a tab from a tiled Firefox
window no longer untiles the original window when the detached window is
tiled.

## Install

1. Download `Tiled-0.2.2.zip` below and move `Tiled.app` to `/Applications`.
2. On first launch, right-click the app and choose **Open** (the bundle is
   ad-hoc signed; there is no Developer ID yet).
3. Grant Accessibility permission when Tiled asks, then relaunch it.

Universal bundle (Apple Silicon and Intel), macOS 13 or later. The attached
`.sha256` verifies the download:
`shasum -a 256 -c Tiled-0.2.2.zip.sha256`.

## What's fixed since 0.2.1

- **A detached tab's window no longer unseats the original.** Firefox opens
  the window a torn-out tab becomes at (within a point of) the source
  window's frame. Identity recovery for churned Accessibility elements
  adopted any same-app window answering at a tiled window's last-read
  frame, so tiling the newcomer moved the original window's record onto it
  and silently untiled the original: it dropped out of the menu while still
  on screen, and the layout kept writing the newcomer's frame. Recovery by
  frame now also requires the held element to be provably stale — the state
  a display teardown leaves behind — so a live window that merely shares the
  frame always keeps its handle.

### Under the hood

- The adoption rule is now a pure policy
  (`LiveWindowGateway.heldElementIsStale` / `inheritedHandle`) with its own
  unit tests, and the mutation table grew four entries for it.
- `tools/repro/handle-collision-repro.swift` covers the shape end to end: a
  freshly focused same-app window parked on a tiled window's exact frame
  must not inherit its handle.

## Quality

- 687 hermetic unit tests over the pure engine through `FakeWindowGateway`,
  a 90-mutant audit where every injected bug is caught, and the live
  end-to-end suites for the pre-release pass.
- No network, no telemetry, no persisted window state; see
  [`SECURITY.md`](https://github.com/edrickt/tiled/blob/master/SECURITY.md).
